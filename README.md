# 社团活动与经费管理系统 · Campus Club Manager

数据库原理课程项目，支持本机运行和 Linux 服务器部署。Python 3.12 + Flask + MySQL 8.0，页面使用 Jinja2、CSS 和少量原生 JavaScript。数据库使用显式 SQL，便于学习查询、外键和事务。

## 启动

独立 Conda 环境名为 `dbxm`。在 Anaconda Prompt 中执行：

```bat
conda activate dbxm
cd /d E:\DBxm
python manage.py init --demo
python run.py
```

浏览器访问 http://127.0.0.1:5000 。也可双击 `start.bat`。关闭启动窗口或按 Ctrl+C 停止。

初次运行前，请填写项目根目录 `.env` 的 MySQL 账号和密码。默认主机 `127.0.0.1`、端口 `3306`、数据库名 `dbxm`。初始化账号需有创建数据库及表的权限。初始化使用 `CREATE ... IF NOT EXISTS`，不删除已有库；演示数据只在用户表为空时写入。请使用独立课程数据库，不与其他项目共用库名。

在其他电脑上可先运行 `conda env create -f environment.yml`，将 `.env.example` 复制为 `.env` 并填写配置，然后按上述命令初始化。已有环境补装依赖：`python -m pip install -r requirements.txt`。

## 已实现的业务

- 用户：注册、登录、退出、修改资料和密码；用户与社团角色分别管理。
- 社团：社团介绍、部门、成员名单、职务调整、退出与恢复；保留历史记录，至少保留一位负责人。
- 招新：创建批次、编辑、预览并发布自定义问卷、选择开放部门、填写技能及可参与时段；审核通过后自动建立或恢复成员关系。
- 活动：草稿、负责人直接发布、修改、取消、结束；报名、取消报名、人数上限和签到；活动变更通知报名成员。
- 经费：多项预算、全额批准或驳回；实际收入与支出单独登记；支出关联已批准申请，累计支出不得超过该申请预算；上传与下载私有凭证。
- 反馈：已签到成员在活动结束后提交评分和意见，负责人整理并保存一份当前复盘。
- 统计：成员人数、专业、年级、部门、已确认技能分布，活动报名与到场率，收支和预算执行情况；按社团、招新批次、收支日期筛选并导出 CSV。
- AI：招新文字整理与技能提取、活动策划草稿、活动复盘。保存每次生成记录；技能需申请人确认后才计入统计。
- 通知与日志：站内通知、已读状态，关键业务操作日志。

招新链接可从批次详情页复制。未登录也可以查看招新说明；通过“学生注册并填写”注册、登录后会返回原问卷。注册固定创建学生角色，不允许自行选择管理员或负责人，填问卷前需要登录，避免同一用户重复提交。签到时间为开始前 30 分钟至结束时间。每次报名只提交一份反馈。凭证支持 PDF / PNG / JPG，总上传请求不超过 10 MB。

## AI 配置

填写 `.env` 并重启：

```ini
AI_BASE_URL=https://服务商的兼容接口地址/v1
AI_API_KEY=你的密钥
AI_MODEL=模型名称
```

调用兼容 Chat Completions 的 `/chat/completions` 接口。不同服务商地址可能不以 `/v1` 结尾，请填写其实际基础地址。密钥只在服务端读取，不显示在页面或日志中。不配置 AI 时，其他模块正常使用，页面会明确提示，系统不会伪造生成结果。

申请人自行发起问卷整理。旧问卷只发送开放题文字；新问卷发送自定义题目的回答，系统不额外发送账号资料，但申请人自行写入回答的个人信息也可能随回答发送。每次调用前都有发送确认。AI 输出经过结构检查，技能依据必须出现在原文中，再由申请人确认；模型建议不作录取或审批决定。活动策划结果可复制到活动编辑页，复盘结果可复制后修改并保存。真实外部模型效果需在配置接口后验证。

## 项目结构与五人协作

| 成员 | 主要文件 | 建议职责 |
| --- | --- | --- |
| 1 | `clubapp/auth.py`、`main.py` 的社团部分 | 用户、权限、社团和成员 |
| 2 | `clubapp/recruitment.py` | 招新问卷、申请审核、技能确认 |
| 3 | `clubapp/activities.py` | 活动发布、报名签到、反馈与复盘 |
| 4 | `clubapp/finance.py` | 经费申请、审批、流水与凭证 |
| 5 | `clubapp/ai.py`、`main.py` 的统计部分 | AI、统计、通知与整体联调 |

共同维护 `clubapp/schema.sql`、测试及页面。建议先约定字段与接口，再分别修改模块，避免多人同时改同一个文件。

`clubapp/db.py` 是 MySQL 连接与查询函数；`templates/` 为中文页面；`static/` 为样式与交互；`instance/` 保存会话密钥和凭证文件；`.env` 保存本机配置。后二者不要提交到版本库。数据库共有 27 张业务表，外键在 SQL 中显式定义。

## 测试

```bat
conda activate dbxm
python -m pip install pytest
python -m pytest -q
```

集成测试连接 `.env` 指向的 MySQL，并创建随机命名的 `dbxm_test_...` 数据库，结束后只删除本次创建的测试库。测试账号需要建库及删库权限。覆盖权限隔离、重复申请、录取入社、报名上限、签到反馈、预算限制、审批权限、AI 证据过滤与人工确认等流程；AI 测试使用模拟返回值，不调用付费接口。

## 当前范围

这是用于数据库课程演示的项目。未包含邮件短信、支付、复杂跳题逻辑、拖拽排版或文件简历解析。财务记录采用正向记账，未做撤销、冲账流程。页面暂未加入大数据量分页，操作日志页面最多展示最近 300 条。Linux 部署使用 Nginx、Gunicorn 和 MySQL，配置示例见 [部署说明](deployment/README.md)。实际密码、AI 密钥、上传文件和数据库数据不包含在仓库中。

## 角色与权限

| 角色 | 主要权限 |
| --- | --- |
| 学生 | 自助注册、填写招新问卷、查看个人录取结果，入社后报名、签到和提交反馈 |
| 社团负责人 | 管理本社团问卷、审核录取、维护部门和成员、直接发布活动、申请经费并登记收支 |
| 管理员 | 全校社团汇总统计、经费审批与收支统筹、社团建档、指定学生负责人 |

管理员不查看个人招新答卷，不发布或关闭招新，不作录取决定，也不审批、修改、取消社团活动。经费申请仍需管理员审批。

负责人权限来自有效的学生社团成员关系，管理员即使保留旧版负责人记录，也不会获得社团日常操作权。对旧版中只有管理员担任负责人的社团，可在社团详情中指定已注册学生。指定操作保留原有学生负责人。

角色调整无需修改数据库表。旧版待审批活动保留原状态和历史记录，负责人可以编辑并直接发布；旧版固定题目招新问卷和答卷继续按原样查看。

## 自定义招新问卷

社团负责人在“招新问卷”中新建批次后，先保存草稿，再添加、修改、删除题目并调整顺序。支持单行文本、多行文本、单选、多选、下拉选择、数字和日期；每道题可设置必填，选择题的选项可逐行填写。最多 30 道题，每道选择题最多 30 个选项。负责人预览并发布后，题目和选项锁定，避免历史答卷与题目不一致。

学生注册登录后填写问卷；负责人可以查看个人答卷、按选项统计人数并导出 CSV。AI 整理自定义问卷时，申请人需再次确认发送回答文字，结果仍由本人确认。旧版固定问卷及已收到的答卷不转换、不删除。

已有安装升级时，先备份数据库，再运行 `python manage.py init` 创建 4 张新表。新建问卷才采用可编辑题目模式。
